THE BIG IDEA

Why analogies are powerful in learning

An analogy connects something students can already manipulate to a concept they cannot directly observe. Here, students already understand that a flipper can redirect a ball. We reuse that intuition to discuss how learned parameters influence information flow.

1ExperiencePlay the physical game.

⚠️
Do not confuse the analogy with the algorithm. Real neural networks use weighted sums, nonlinear activation functions, loss functions and gradient-based optimization. The pinball model is a visual bridge that helps students build the right intuition before those equations appear.

CREDIT ASSIGNMENT

Who should receive the blame?

If a ball reaches the wrong output, we should not randomly change every flipper. We ask: which parameters actually influenced this ball's journey?

That is the intuition behind credit assignment. In real deep learning, backpropagation uses gradients to send responsibility backward through the network. In this teaching game, the physical collision history provides a visible simplified version of that idea.

QUESTION 1

Why can't we hard-code the answer?

Because we want the system to discover reusable patterns from examples rather than write a rule for every possible input.

QUESTION 2

Why do we need many layers?

Different layers can transform representations so later computation can use increasingly useful combinations of earlier features.

QUESTION 3

What does “learning” really mean?

It means changing parameters so that the model's future behavior becomes more useful on the training objective.

The teaching idea

Every moving flipper carries three spaced spring dots, and every dot has its own numerical weight. Initially the dot weights are random. A ball represents one pixel of an 8×8 digit image: exactly 64 equal-size balls represent 64 pixel values, arranged in a horizontal row in flattened-vector order. Initial downward velocity represents pixel intensity. Note: the standard MNIST dataset uses 28×28 images (784 pixels); this 64-ball teaching setup matches an 8×8 digit dataset representation.

spring dot: learnable weight wᵢ dot radius: r = r₀ + c × |wᵢ| upward impulse: vᵧ ← −(base + scale × |wᵢ|) global flipper speed: shared speed slider = activation analogy learning: wᵢ ← clip(wᵢ + learning_rate × error signal)

The game deliberately simplifies backpropagation so students can see the central idea: the parameters are changed repeatedly because the output was wrong. The important point is that each flipper owns its own parameter; different flippers learn different speeds.

Per-layer freeze timer: every layer has its own independent timer. All balls keep moving continuously through the whole board; when a layer timer expires, that layer's flippers smoothly return to the horizontal position and then freeze there. No layer hand-off or waiting is applied to balls. This timing is a physical teaching analogy, not a literal clock in ordinary feed-forward neural networks.

No separate activation bar: the flipper's shared movement speed is the activation-function analogy. It is intentionally not a mathematical activation function; real networks apply nonlinear functions to weighted sums.

Spring-dot weights: each flipper carries spaced, individually learnable spring weights. A spring pushes along the normal perpendicular to its flipper, so an angled flipper can send a ball diagonally. Weight magnitude controls impulse strength, and the flipper's motion can add tangential velocity. The spring can change both horizontal and vertical ball velocity.

Batch learning: exactly 64 equal-size balls are released in one horizontal row, one per flattened pixel. Pixel intensity controls initial downward velocity. After the forward pass, the game computes prediction = container count / 64, then error = one-hot target − prediction. Each spring dot receives only the error carried by balls that physically hit it. This is an educational credit-assignment analogue, not literal backpropagation gradients.
